## 第 1 页｜作品背景与说明

### 页面标题

职航智管：让每一次求职行动都有下一步

### 页面正文

- 面向高校应届毕业生和就业辅导员的就业事务智能体。
- 将就业画像、职业规划、岗位匹配、简历优化、模拟面试、投递管理、学习成长、入职后训练和企业反馈连接成一个可追踪闭环。
- 学生端解决“目标不清、任务难执行、材料分散、反馈难沉淀”；辅导员端解决“进展难掌握、风险难解释、帮扶难闭环”。
- 核心设计：模型负责理解、分析和提出建议；业务系统负责事实记录、权限校验、工具执行和人工确认。

### 参考来源

- 高校毕业生就业指导与帮扶业务流程。
- 公开就业服务平台的岗位信息结构。
- 项目自建的脱敏岗位、简历、面试和就业事务样例。

### 页面视觉

- 左侧放“学生求职闭环”流程：建档 → 规划 → 匹配 → 准备 → 投递 → 面试 → 复盘 → 入职反馈。
- 右侧放学生端、辅导员端和 Agent 的三层关系图。

### 讲解要点

本作品不是只回答问题的聊天机器人，而是把建议落实为有状态、有证据、可确认、可审计的就业事务工作流。

## 第 2 页｜问题场景与用户需求

### 页面标题

求职信息分散，指导服务缺少连续反馈

### 页面正文

| 角色 | 真实工作痛点 | 系统对应能力 |
| --- | --- | --- |
| 应届毕业生 | 不知道适合什么岗位；简历、岗位、投递和面试记录分散；计划难坚持 | 就业画像、目标岗位、四周计划、岗位匹配、简历优化、模拟面试、投递看板 |
| 就业辅导员 | 学生状态依赖人工收集；难以快速发现停滞；帮扶结果难跟踪 | 班级驾驶舱、风险事实、学生分层、帮扶任务、就业质量与审计 |
| 就业管理者 | 缺少可解释的过程数据和反馈回流 | 脱敏汇总、投递漏斗、入职回访、企业评价、课程改进依据 |

### 页面底部结论

系统把“问一个问题”转化为“读取事实 → 分析差距 → 生成行动 → 用户确认 → 记录结果 → 下一轮复盘”。

### 页面视觉

- 使用三列痛点卡片，底部用一条闭环箭头连接学生、辅导员和就业管理。

### 讲解要点

强调项目服务的是连续求职过程，Agent 的价值在于理解上下文并推进下一步，而不是输出一次性的泛化建议。

## 第 3 页｜数据来源与权威性

### 页面标题

多来源数据进入统一岗位与知识体系

### 页面正文

| 数据来源 | 引入内容 | 权威性与时效性 | 系统用途 |
| --- | --- | --- | --- |
| 国家级或公共就业服务平台公开岗位 | 岗位名称、企业、地点、岗位描述、来源链接、抓取时间 | 来源可回溯；以来源页面当前内容为准 | 岗位情报、岗位候选库、匹配分析 |
| 企业或招聘机构公开职业页面 | 校招公告、职位要求、招聘批次、职位链接 | 由来源站点发布；需要验证发布时间和有效期 | 岗位来源适配器、岗位新鲜度提醒 |
| 项目脱敏业务样例 | 脱敏简历、岗位描述、面试题、任务、政策和办事说明 | 用于开发、测试和现场演示，不替代官方统计 | 知识库、回归测试和流程演示 |

### 采集原则

- 保存来源 URL、来源主机、来源类型、抓取时间和可信等级。
- 公开网页岗位只用于检索、比较和分析，不自动投递。
- 来源失效、内容过期或字段缺失时，前端明确提示核验。

### 页面视觉

画一个“来源 → 清洗 → 记录来源 → 进入知识库/岗位库”的数据流图。

### 讲解要点

项目把来源可信度和时效作为岗位数据的一部分，回答时能指出依据来自哪里、什么时候获取。

## 第 4 页｜知识库内容设计

### 页面标题

按就业任务组织知识库，让回答有出处

### 页面正文

知识库分为四类：

1. **岗位知识**：岗位职责、技能要求、地点、来源链接和有效时间。
2. **求职材料知识**：简历结构、岗位关键词、证据表达和面试评分量表。
3. **就业事务知识**：投递流程、笔试面试准备、入职跟踪、企业反馈维度和复盘规则。
4. **公共指导知识**：公开就业政策、办事流程和校内流程说明；使用时展示来源和发布日期。

### 知识条目结构

`内容片段 + 来源类型 + 来源 ID + 发布时间/抓取时间 + 适用范围 + 脱敏状态 + 向量索引`

### 使用约束

- 检索结果先经过用户和资源范围过滤，再提供给 Agent。
- 检索不到可靠材料时，回答明确标注“未匹配到可引用来源”。
- 个人简历片段只对本人和授权辅导员可见。

### 页面视觉

展示一个知识条目详情框，并用标签标记“来源、时间、权限、可引用”。

### 讲解要点

知识库不是把所有文字堆在一起，而是让每个回答都能回到来源片段和适用范围。

## 第 5 页｜数据预处理与向量检索

### 页面标题

从 PDF 简历到可引用的就业证据

### 页面正文

```text
上传 PDF/DOCX
      ↓
文件类型与大小校验
      ↓
PDF 强制进入 OCR 链路；DOCX 进入文档解析链路
      ↓
文本清洗、分段、页码与置信度记录
      ↓
BGE-M3 生成 1024 维向量
      ↓
PostgreSQL + pgvector 保存向量和来源关系
      ↓
按权限过滤后进行相似度检索
      ↓
Agent 引用片段，生成结构化结论
```

### 技术实现

- PaddleOCR：扫描 PDF 和图片文字识别，异步任务状态为 `queued/running/succeeded/failed`。
- BGE-M3：独立 CPU 服务，负责简历、岗位、课程和业务知识的向量化。
- PostgreSQL + pgvector：保存业务事实、来源关系和向量索引。
- Worker + Redis：承载 OCR、向量化、语音和其他耗时任务。

### 质量控制

- 记录页码、解析状态和 OCR 置信度。
- 解析失败允许重试或手工录入。
- Agent 只能使用已经检索到的授权片段，不能凭空补写经历。

### 页面视觉

使用横向流水线，底部加“可追溯、可权限过滤、可重试”三个质量标签。

### 讲解要点

数据处理的最终目标是把原始材料变成带来源的证据，而不是只生成一段看似流畅的文字。

## 第 6 页｜分析方法选择

### 页面标题

规则、检索、评分和 Agent 协同分析

### 页面正文

| 分析方法 | 适用问题 | 选择依据 |
| --- | --- | --- |
| 规则引擎 | 连续无投递、计划逾期、面试未通过等风险 | 可解释、可复核、结果稳定 |
| 语义检索 | 简历与岗位、课程与能力差距、知识问答 | 能处理自然语言表达差异，保留引用片段 |
| 五维岗位匹配 | 硬性条件、技能、经历、偏好、发展方向 | 将“适合/不适合”拆成可比较维度 |
| 结构化评分量表 | 面试内容、岗位相关性、表达结构、证据质量 | 评分维度固定，便于多轮对比 |
| 多 Agent 工作流 | 复杂问题需要多类专业判断 | 主 Agent 负责路由，专业 Agent 负责单一职责 |

### 评分原则

- 评分结果必须有输入证据或规则事实。
- 面试评分采用统一版本量表 `unified-v1`，摄像头表达稳定度作为可选训练参考维度。
- 风险规则不使用性别、民族、家庭情况等敏感属性，也不预测“能否就业”。

### 页面视觉

用四象限或“确定性规则 / 语义分析 / 结构化评分 / Agent 编排”矩阵展示。

### 讲解要点

模型适合处理语言理解和综合分析，确定性业务规则仍由后端执行，二者互相校验。

## 第 7 页｜问题理解与 Agent 逻辑论证

### 页面标题

主 Agent 先判断意图，再调用专业 Agent 和业务工具

### 页面正文

```text
用户问题
  ↓
会话网关：读取持久会话、角色和当前业务上下文
  ↓
主 Agent：识别意图、拆解步骤、选择专业 Agent
  ↓
专业 Agent：职业规划 / 岗位 / 简历 / 投递 / 面试 / 辅导员 / 职场训练
  ↓
后端提供授权工具目录
  ↓
角色校验 + 学生归属校验 + 参数契约校验 + 风险级别校验
  ↓
读取事实或形成动作提案
  ↓
流式事件回传：Agent、工具、引用、结论、错误和耗时
  ↓
持久化回答与业务状态
```

### 关键论证

- 模型可以提出工具候选，但不能创建工具、扩大工具权限或绕过业务规则。
- 专业 Agent 不直接修改数据库，写操作通过注册工具执行。
- 删除、批量修改、代替学生提交外部申请等高风险动作始终需要二次确认或保持不可执行。

### 页面视觉

用泳道图区分“模型层、授权层、业务层、数据层”。

### 讲解要点

这是项目的核心技术边界：模型负责规划，后端负责授权和执行，所有过程可以展开查看。

## 第 8 页｜数据实例与分析结果

### 页面正文示例

`简历片段 → 岗位要求 → 投递状态 → 面试评分 → 行动建议`

## 第 9 页｜分析流程思维导图

### 页面标题

从个人事实到持续改进的闭环分析

### 页面正文

```text
就业事实
├── 个人档案与简历证据
├── 目标岗位与岗位来源
├── 投递、笔试、面试状态
├── 学习任务与训练结果
└── 入职后交付与企业反馈
        ↓
证据加工
├── OCR / 文档解析
├── 文本分段与向量化
├── 来源与时效记录
└── 角色与资源权限过滤
        ↓

├── 画像与差距
├── 岗位匹配
```

### 页面视觉

## 第 10 页｜创新点展示

### 页面标题

两项创新：可审计的多 Agent 协作与入职前后连续训练

### 页面正文

#### 创新点一：可观测的 Agent 工具运行

- 主 Agent 组织专业 Agent 协作。
- 工具目录按角色和专业 Agent 过滤。
- 每次运行记录任务、工具、脱敏输入输出、结论、错误码、开始时间、结束时间和耗时。
- 用户可在“确认后执行 / 自动执行”之间调整权限；高风险动作仍需二次确认。

#### 创新点二：从求职前延伸到入职后

- 入职前：岗位匹配、简历优化、模拟面试和求职事务管理。
- 入职后：任务澄清、行动计划、风险清单、会议纪要、周报和交付物复盘。
- 企业评价以一次性邀请提交，经过匿名阈值和权限控制后用于就业质量与课程改进。

### 页面视觉

左右两条纵向链路：`Agent 可审计` 与 `求职到入职闭环`，中间用“就业结果反馈”连接。

## 第 12 页｜结果解读：学生端闭环

### 页面标题

学生从建档开始，获得一条可执行的求职路径

### 页面正文

1. 上传脱敏简历，OCR/文档解析形成结构化草稿。
2. 学生确认个人经历、能力证据和求职约束。
3. Agent 推荐主目标岗位和备选路径，说明匹配依据与差距。
4. 四周计划拆成带截止时间和验收标准的任务。
5. 岗位匹配、简历版本、模拟面试和投递状态互相引用。
6. 每周复盘读取真实过程数据，生成不超过三项下一周行动。

### 应用价值

- 学生知道“当前差距是什么、下一步做什么、完成标准是什么”。
- 每次建议都能关联到简历、岗位、投递、面试或任务事实。
- 学生可以修改、拒绝或确认 AI 草稿，保留自主决策权。

### 页面视觉

展示学生工作台截图，标出“目标、任务、投递漏斗、AI 建议、复盘”五个区域。

## 第 13 页｜结果解读：辅导员端闭环

### 页面标题

辅导员看到风险事实，也看到下一步帮扶动作

### 页面正文

### 班级驾驶舱

- 班级学生数、活跃学生数、目标建立数、近七日投递数、面试数、录用数。
- 风险学生按“正常 / 关注 / 需干预”分层。

### 风险解释

- 连续 14 天无投递记录。
- 四周计划逾期 3 项及以上。
- 投递达到阈值但没有笔试或面试反馈。
- 连续面试未通过，需要模拟面试或人工辅导。

### 帮扶闭环

`规则触发 → Agent 归纳 → 辅导员确认 → 布置任务 → 学生反馈 → 辅导员验收 → 审计留痕`

### 页面底部说明

风险规则提供线索，不自动给学生排名、处分或限制资源；辅导员必须可以查看事实并人工确认。

## 第 14 页｜结果解读：模拟面试与表达训练

### 页面标题

AI 出题、动态追问、流式回答和多维评分

### 页面正文

- 结构化岗位面试默认包含 6 个核心问题，并最多追加 2 个追问；场景面试可使用数据库配置的步骤。
- 问题根据岗位描述和简历证据生成，中文兜底机制避免英文重题或乱码内容。
- 回答通过流式接口返回，前端按 `started → delta → evaluated → completed` 事件更新页面。
- 统一评分维度：内容完整度、岗位相关性、表达结构、证据质量。
- 摄像头可选开启：YOLO 检测人脸框，本地表情模型生成表达稳定度训练参考；每 1 秒采样，最多保留统计结果，不保存原始视频或图片。

### 结果解释示例

“回答与岗位相关性较高，但证据质量不足；请补充本人承担的具体工作、验证方法和量化结果。”

### 伦理边界

摄像头结果仅用于表达训练参考，不用于心理诊断、录用判断、性别判断或外貌评价。

### 页面视觉

放数字人面试官、中文对话、评分雷达图和可选摄像头标注框截图。

## 第 15 页｜问题与可行优化建议

### 页面标题

当前 Agent 的问题与后续优化路线

### 页面正文

| 当前问题 | 影响 | 优化措施 |
| --- | --- | --- |
| 公开网页岗位结构可能变化 | 个别来源字段缺失或抓取失败 | 增加来源适配器、重试、字段校验、来源新鲜度监控和人工核验入口 |
| 模型回答存在不确定性 | 可能给出过宽或不够具体的建议 | 强化检索引用、结构化 JSON 契约、证据校验和人工确认 |

| 训练评分需要更多样本校准 | 单次结果不能代表长期能力 | 引入多轮趋势、人工复核样本和版本化评分量表 |

### 优先级

1. P0：全链路可观测、模型超时/重试、工具授权和故障恢复。
2. P1：题库人工审核、岗位来源监控、评分趋势和浏览器 E2E。
3. P2：并发压力测试、成本统计、对象存储迁移、监控告警和数据保留策略。

### 页面底部说明

优化目标是提升稳定性和可解释性，不扩大 Agent 的自动执行权限。

## 第 16 页｜风险识别与应对

### 页面标题

把数据、模型和业务动作风险关在系统边界内

### 页面正文

| 风险 | 可能后果 | 应对策略 |
| --- | --- | --- |

可访问、可演示、可追溯的 Agent 作品

### 页面正文

### 智能体链接

- 智能体访问地址：`【提交前填写已部署的评审链接】`
- 评审账号：`【提交前填写专用评审账号】`

- 链接和账号只放在赛事提交平台或赛事要求的安全位置，不写入公开视频、公开仓库或 PPT 截图。

### 推荐演示方式

- Docker 全量运行：前端、FastAPI、PostgreSQL/pgvector、Redis、Worker、BGE-M3、PaddleOCR、FunASR、MeloTTS 和 Emotion 服务在同一网络中运行。
- 评审入口优先展示：就业助手 → 执行详情 → 岗位情报 → 模拟面试 → 辅导员驾驶舱。
- 现场准备一条已有完整结果的脱敏会话和一条备用会话，避免等待外部模型或公开网页响应。

### 结尾文案

职航智管把个人成长、求职事务和就业服务连接成一个可解释的 Agent 闭环：学生知道下一步，辅导员知道为什么，系统保留每一步依据。

### 提交前自检

- PPT 页数不超过 20 页，画面比例为 16:9，文件小于 50 MB。
- 视频不超过 6 分钟，MP4 小于 300 MB，画面和声音清晰。
- PPT、视频、智能体页面和截图均无学校、学生、指导教师、学号、手机号、邮箱等身份信息。
- 所有“真实数据”均有来源、时间和样本量；演示数据明确标注“演示数据”。
- 智能体链接可访问，评审账号权限足够且不含个人隐私。
