# 职航智管求职训练与职业成长服务系统｜比赛项目介绍

**评审维度：**技术创新 30%｜场景落地 30%｜开源治理 20%｜长期发展 20%  
**版本：**V1.0  
**编制日期：**2026-10-25

## 1. 项目定位

职航智管面向高校毕业生和就业辅导人员，把就业画像、四周计划、岗位匹配、简历优化、模拟面试、投递管理、学习成长、入职后训练和反馈回流组织成一个可追踪的业务闭环。模型负责理解与提出建议，后端负责事实、权限、工具执行和审计。

## 3. 技术创新

- **证据优先：**画像、岗位、任务、申请和面试结果作为业务事实，回答携带来源片段。
- **可控编排：**主 Agent 规划步骤，专业 Agent 处理单一职责，不能直接改数据库。
- **授权工具：**后端重新检查角色、资源归属、参数契约和风险等级。
- **持久可追溯：**会话、消息、运行状态、工具调用和动作提案写入服务端。
- **训练边界：**模拟面试与职场训练分域，摄像头分析仅用于表达训练参考。

## 4. 场景落地

### 学生

学生可以从就业画像和简历材料开始，确认能力证据和目标岗位，生成四周计划，在岗位匹配、简历优化、模拟面试、投递看板和每周复盘之间持续推进。

### 辅导员

辅导员可以查看班级概览、风险事实和学生进展，建立帮扶任务，接收学生反馈并确认完成。风险规则提供线索，不自动给学生排名或限制资源。

### 入职后

职场工作台从工作简报读取岗位、阶段、目标、协作对象、截止时间和验收标准，学生形成真实交付物，提交结构化评审和复盘。

## 5. 开源治理

当前工作区没有配置公开 Git remote，因此代码仓库链接暂留：`【提交前填写仓库 HTTPS URL】`。发布前应完成：

1. README、部署文档、环境变量模板和快速启动路径同步到仓库首页。
2. 删除密钥、数据库文件、个人简历、演示密码和本地输出。
3. 建立 Issue、PR 和安全问题模板，要求复现步骤、影响范围和验证结果。
4. 为评审版本打 tag，附 CHANGELOG 和已知限制。
5. 接入 CI，至少运行后端测试、前端测试、构建和关键 E2E。

## 6. 长期发展

- **阶段一：**完成公开仓库、评审链接、脱敏素材和可复现演示。
- **阶段二：**与高校就业部门共同校准风险规则、面试量表和权限流程。
- **阶段三：**完善岗位来源适配、任务队列、监控、成本和数据保留。
- **阶段四：**支持多学校和多角色，形成课程改进与就业质量反馈。

## 7. 测试与数据边界

本次记录显示后端 63/63、前端组件 25/25、API 流程 22/22、风险规则边界 15/15；现有浏览器回归仍有 5 项待处理。演示库包含 24 名人工构造学生、6 个演示岗位、85 条申请记录、96 项计划任务和 9 条风险事件。这些数字不代表真实用户、真实投递或就业成效。

匹配分和面试分是本地规则演示输出，不是算法准确率、录用概率或能力提升率。在线模型、OCR、语音和视觉服务的可用性取决于部署环境。
