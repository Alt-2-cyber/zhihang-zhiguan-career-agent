# 职航智管贡献与版本治理方案

本文件是2026-10-25文档整理时补充的方案，供项目方采用和完善；不表示公开仓库、许可证、CI或团队角色分配已经落实。软件项目的权利主体、实际许可证及公开联系方式由项目方确认。

## 问题登记

功能问题应包含环境与部署模式、版本或commit、最小复现步骤、实际与期望结果、脱敏日志、数据样本性质。影响个人资料、令牌或权限的问题不要在公开Issue粘贴原始材料；在项目方设立私密报告渠道后通过该渠道提交。

## Pull Request

说明对应Issue、行为变化、涉及的接口和数据迁移、授权影响、测试结果和已知限制。更改量表、工具或提示词时注明版本差异。维护者核验前后端字段、权限与资源归属、事务边界、幂等行为和错误提示，不以界面截图代替逻辑验证。

## 验证

后端运行ruff和pytest，前端运行lint、组件测试与构建；关键浏览器检查指向隔离的E2E环境。不得连接真实用户库、批量更改生产状态或将历史通过数写成当前版本结果。测试失败时保留证据。

## 发布

为评审版本打tag并生成变更记录，注明迁移、配置、已知问题和恢复步骤。发布前在干净环境复现启动和关键流程；检查依赖、模型、图片和改编代码的来源与许可。未核实项目授权前，不添加虚构权利人的LICENSE。

## 后续责任

项目维护、业务校准、安全隐私、运维和文档责任待团队确认后填写。路线分为提交准备、授权试点、稳定运营和多组织扩展，各阶段以记录和验收结果推进，不预设未经承诺的日期或用户规模。
