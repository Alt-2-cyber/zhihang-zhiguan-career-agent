# 《职航智管》网站演讲稿与现场演示脚本

> 建议时长：8-10 分钟
>
> 演示入口：http://127.0.0.1:8080/
>
> 演示账号：学生 `student_demo / Student123!`；辅导员 `counselor_demo / Counselor123!`

## 一、开场：项目定位（约 40 秒）

各位评委好，我介绍的项目是“职航智管”，一个面向高校毕业生和就业辅导员的 AI 就业规划与求职事务智能agent平台。

## 二、登录页：统一入口与角色权限（约 30 秒）

### 讲解词

首先看到的是统一登录入口。学生和辅导员使用同一套身份体系进入不同工作区，

### 同步演示

1. 使用学生演示账号登录。
2. 指向左侧导航，说明学生工作区包含规划成长、求职行动和入职后成长三个阶段。
3. 退出后使用辅导员账号登录，展示导航自动切换为班级概览、学生进展、帮扶任务和系统治理。

## 三、学生工作台 `/student`：先看今天该做什么（约 45 秒）

### 讲解词

登录后进入学生工作台。这里不是一个只展示数据的首页，而是求职执行的总入口。

## 四、就业画像与简历 `/student/profile`、`/student/resume`（约 55 秒）

### 讲解词

就业画像是整个系统的事实基础。学生可以在简历管理中上传 PDF 或 DOCX，也可以在画像页粘贴简历文本，填写目标城市和目标行业。

系统会从材料中提取能力、经历、优势、能力缺口和求职约束，并把每个结论绑定到原文证据。AI 生成的画像先进入“待确认”状态，学生确认以后才写入正式档案。

简历优化也遵循同样原则：建议会把原文、修改建议和理由分开显示，不自动编造经历。每个业务页都提供“询问 Agent”入口，可以只围绕当前简历或当前画像提问。

### 同步演示

1. 打开“简历优化”，展示已解析简历和解析状态。
2. 进入“就业画像”，指向“能力与证据”“能力缺口”“求职约束”三部分。
3. 点击“生成就业画像”，展示待确认结果；说明现场只确认真实内容，不为演示补写经历。

## 五、四周求职计划 `/student/plan`（约 45 秒）

### 讲解词

有了画像以后，系统把目标岗位拆成四周行动计划。计划包含主目标岗位、备选方向、每周任务、截止日期和验收标准。

### 同步演示

1. 输入“数据分析师”并生成计划。
2. 展示四周任务和验收标准。
3. 点击“确认计划”，说明确认后任务才进入正式执行链。

## 六、就业助手 `/student/assistant`：主 Agent 协同专业 Agent（重点，约 1 分 50 秒）

### 讲解词

这是项目的 AI 核心页面。左侧是可搜索、可归档的持久会话，中间是中文对话，右侧是执行详情和工具调用。

学生提问，主 Agent 会先识别意图，再把任务分给职业规划、岗位匹配、简历、投递、面试或辅导员专业 Agent。专业 Agent 不直接修改数据库，只能从已注册工具目录中选择工具。

工具调用前，后端会重新校验四件事：当前角色是否允许调用、资源是否属于当前用户、参数是否符合契约、操作风险是否需要确认。模型提出的是候选动作，最终是否执行由后端授权和用户权限决定。

页面顶部可以切换“确认后执行”和“自动执行”。读操作可以直接完成；删除、批量修改和代替学生提交外部申请等高风险操作必须二次确认。每次运行都会记录 Agent 任务、工具、脱敏输入输出、结论、错误、时间和耗时，便于解释和审计。

对话通过服务端事件流按顺序接收状态、工具和回答事件，所以用户能看到 Agent 正在做什么；刷新页面后，消息和执行记录仍然从服务端恢复，不会重复显示。

### 同步演示

1. 选择一条已有完整结果的历史会话，指向左侧持久会话。
2. 发送上面的综合问题。
3. 等待执行过程中，展开右侧专业 Agent 和工具调用。
4. 指向数据来源、脱敏参数、风险级别和耗时。
5. 展示权限下拉框，保持“确认后执行”。

### 这一页的技术亮点

- 主 Agent 编排专业 Agent，专业 Agent 只能调用后端注册工具。
- 会话、消息、运行状态和动作提案持久化到数据库。
- SSE 事件流支持状态、工具和回答的流式回传。
- Provider 有超时、重试和故障转移；失败时展示真实错误，不伪造成功。
- 操作日志脱敏，支持确认、拒绝、撤销和失败重试。

## 七、岗位匹配与岗位情报 `/student/jobs`、`/student/intelligence`（约 55 秒）

### 讲解词

岗位匹配页把已确认画像与岗位放在一起，从硬性条件、技能、经历、偏好和发展方向五个维度计算匹配度，并展示每个分数对应的证据、能力缺口和下一步动作。

岗位情报页关注的是市场侧信息。系统实时聚合公开招聘来源，展示岗位数量、热门岗位、热门城市、活跃企业、来源状态和岗位新鲜度。点击“同步公开岗位”后，后端会按来源适配器执行采集并记录成功、失败和导入数量。

### 同步演示

1. 在岗位匹配页选择岗位，点击“开始五维匹配”。
2. 指向匹配分数和证据引用。
3. 进入岗位情报页点击“同步公开岗位”。
4. 展示来源状态、更新时间和失败来源，不把不稳定的网页抓取说成商业招聘 API。

## 八、模拟面试 `/student/interview` 与会话页 `/student/interview/:sessionId`（重点，约 1 分 20 秒）

### 讲解词

模拟面试，选择简历和目标岗位后，点击开始，

会话页采用数字人面试官界面。AI 根据简历、岗位和当前回答动态出题，问题和点评通过流式响应返回；学生可以文字回答，也可以按住录音后提交。数字人支持问题朗读，语音由独立语音服务异步生成。

每轮回答会生成内容完整度、岗位相关性、表达结构、证据质量等评分，并给出下一步建议。学生开启摄像头，系统还会用本地yolo算法视觉服务进行人脸和表达稳定度采样

### 同步演示

1. 选择一份已解析简历和一个目标岗位。
2. 点击“开始模拟面试”，说明页面会跳转到独立会话。
3. 指向中文题目、数字人头像、朗读按钮和摄像头分析开关。
4. 输入一段回答，点击提交，展示流式点评和评分维度。
5. 说明高压面试可以调整压力等级，所有状态会保存到会话记录。

## 九、学习成长与 AI 考试 `/student/learning`、`/student/training`（约 45 秒）

### 讲解词

学习成长页把能力差距转成学习任务、课程资源和完成证据。页面展示能力雷达、趋势变化和薄弱项，

训练中心提供 AI 出题和考试流程。题目进入结构化题库后，考试支持倒计时、草稿恢复、逐题作答、自动提交和成绩报告。学习记录和考试结果会进入后续 Agent 上下文，为求职计划和面试建议提供事实依据。

### 同步演示

1. 展示能力雷达和薄弱项。
2. 打开一项学习任务，填写证据并提交。
3. 进入一场 AI 考试，展示题目、倒计时和答题状态。

## 十、职场训练 `/student/workplace`：与模拟面试区分（约 55 秒）

### 讲解词

模拟面试解决的是入职前的求职表达；职场训练解决的是入职后的真实工作问题，两者在产品上完全分开。

职场训练从场景库开始，例如任务澄清、交付协作、跨部门沟通和工作复盘。进入场景后，系统生成工作简报、完成标准和交付历史。学生可以手写交付物，也可以让 Agent 根据简报生成草案，再由学生核对和提交。

Agent 只能生成工作草案，不能替学生向外部系统提交，也不会把未经确认的内容写成事实。场景过程、材料引用、草案版本和最终反馈都会留下记录，形成入职后的成长证据。

### 同步演示

1. 打开“职场训练”，选择一个入职后场景。
2. 展示工作简报、验收标准和素材引用。
3. 进入交付编辑器，生成一份草案并修改后保存。
4. 强调该页面与入职前模拟面试的目标和数据完全不同。

## 十一、投递、入职跟踪与每周复盘 `/student/applications`、`/student/employment`、`/student/review`（约 55 秒）

### 讲解词

投递管理页记录每个岗位从收藏、投递、笔试、面试到录用的状态变化。普通状态更新可以由学生主动完成；高风险批量修改和代投行为仍然需要确认，不会因为接入 Agent 就绕过人的决定。

当一条投递进入录用状态，学生可以把它转换为就业记录，进入 7 天、30 天、90 天和 180 天回访。学生端可以评价岗位一致性、工作强度、带教、团队氛围、薪酬兑现和成长空间，并填写企业真实要求、面试流程和给后来者的建议。

学生授权后可以生成一次性企业评价邀请。企业通过公开链接填写近期表现、适岗速度、专业技能、沟通协作和任务质量，提交后链接自动失效。原始评价先进入审核和脱敏流程，再用于就业质量分析和课程改进。

每周复盘根据最近七天的真实投递事件计算漏斗，输出数据洞察和最多三项下周优先行动，把“复盘”重新接回下一轮计划。

### 同步演示

1. 在投递看板把一条岗位展示到面试或录用状态。

2. 进入入职跟踪，展示四个回访节点和双向反馈。

3. 说明企业评价邀请只展示一次，不能重复使用。

4. 点击“生成本周复盘”，展示投递、回复、笔试、面试和录用数据。

## 十二、辅导员端 `/counselor`：从看结果到做帮扶（约 1 分钟）

### 讲解词

切换辅导员账号后，首页变成班级就业概览。辅导员能看到班级学生数、累计投递、风险学生数和风险分布，例如连续多天没有投递、任务逾期或面试后没有复盘。

学生进展页用于查看学生状态和求职漏斗；帮扶任务页用于布置任务、接收学生反馈和闭环跟踪；就业质量页汇总经过审核和匿名阈值保护的企业反馈，帮助学校发现课程与岗位要求之间的差距。

就业助手页面支持辅导员围绕指定学生进行对话，但会话范围、数据权限和工具白名单仍由后端控制。系统治理下的 Agent 运行统计和审计日志，可以查看模型调用次数、耗时、失败率、工具执行和高风险动作，保证 AI 的行为可解释、可追溯。

### 同步演示

1. 使用辅导员账号登录，展示班级概览。
2. 点击一名风险学生，指向风险触发原因。
3. 创建一条帮扶任务，填写目标和截止日期。
4. 打开 Agent 运行统计或审计日志，展示一次 Agent 调用的时间、工具和结果。



## 十四、结尾（约 30 秒）

职航智管解决的不是“再做一个聊天机器人”，而是把 AI 放进真实的就业事务流程里：学生从事实画像出发，得到计划、岗位、面试和学习行动；辅导员从可解释的风险事实出发，完成分层帮扶；入职后，学生和企业的反馈又回到学校的课程和就业质量改进。
